1. Overview

Dorm Manager uses a MySQL relational database managed through Laravel's Eloquent ORM and migration system. The schema is designed around the core billing workflow:

  1. A Room has a monthly rate and a capacity (max beds).
  2. A Contract links one or more Tenants to a Room for a period.
  3. Each month, one Invoice is generated per Room (per active contract).
  4. The invoice is automatically split into per-tenant TenantPayment rows.
  5. Each Payment records money received and optionally links to the specific TenantPayment row it settles.

Role-based access control is provided by the Spatie Laravel Permission package (v6), which adds the roles, permissions, model_has_roles, and related tables.

ColumnTypeDescription

5. Key Business Rules Enforced by the Schema

5.1 Rent Splitting

Rent is not stored per tenant. Instead:

  • rooms.monthly_rate = full room cost.
  • invoices.tenant_count = snapshot of tenants at generation time.
  • tenant_payments.share_amount = total_amount ÷ tenant_count (calculated at invoice generation).

This means if a room has 4 tenants at ₱10,000/month, each tenant_payments row gets share_amount = ₱2,500.

5.2 Invoice Status Derivation

The invoice status is computed from all its tenant_payments rows:

Tenant payment statusesInvoice status
All = paidpaid
Some paid, rest anythingpartial
None paid, all = overdueoverdue
None paid, all = latelate
None paid, any late/overdue mixed with pendinglate
None paid, all = pendingpending

5.3 Electricity Billing

Electricity cost = meter_readings.kwh_used × settings.value (where key='electricity_rate' and effective_from ≤ billing month end). Past invoices are never retroactively updated when the rate changes.

5.4 Audit Log Immutability

The audit_logs table has no updated_at column and no UPDATE or DELETE operations in the application code. It is append-only.

5.5 PayMongo Webhook Matching

When PayMongo sends a payment webhook:

  1. Match by tenant_payments.paymongo_link_id (most precise — links to specific tenant's payment).
  2. Fall back to invoices.paymongo_link_id.
  3. Fall back to invoice_number in the payment description/remarks.
